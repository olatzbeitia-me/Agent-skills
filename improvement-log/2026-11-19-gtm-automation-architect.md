## What changed

1. **Guarding agents against untrusted input (new guardrail).** `references/build-test-iterate.md` gains a section on prompt injection: an AI step that reads outside text (demo form messages, prospect websites, inbound emails, call transcripts, partner data) can be steered by instructions hidden in it. The design rules: an agent that reads outside text holds no send, owner-change or overwrite tools; its output passes rule-based checks before anything acts on it; the existing approval gates are treated as a security control; outside text is labelled as data in the prompt; no reliance on blocking phrases; full logging of inputs, outputs and tool calls. The blueprint's AI steps table now records whether a step reads outside text and which tools it may call, the monitoring table alerts on refused or unusual tool calls, and `SKILL.md` adds one rule to "Rules for agentic steps".
2. **Testing AI steps properly (sharper method).** A new section in the same reference covers what a single pass over the golden set misses: run each AI step several times per record and report both the single-run hit rate and the share of records right on every run; balance the set with "do nothing" cases; use rules wherever one answer is right and a model grader only for judgement calls, compared with a human reviewer first; check what landed in the CRM rather than the agent's report; read failures to separate agent errors from test errors; keep the golden set as a regression suite after promotion. The golden set gains 2 edge cases (records where the right result is to do nothing, and records with a planted instruction), and the acceptance criteria table gains consistency and planted-instruction rows. `SKILL.md` phase 5 summarises this in 3 new bullets.
3. **UK compliance reference brought up to date.** `references/compliance-uk-eu.md` now records that the Data (Use and Access) Act 2025's data protection provisions are all in force (higher electronic marketing fines from 5 February 2026), that the regulator calls the direct marketing wording a clarification (so the balancing test stays), and when the detailed guidance was last updated. It adds 3 points from the Information Commissioner's Office electronic mail guidance that matter for go-to-market stacks: private social media messages, LinkedIn included, count as electronic mail; publicly found or enriched contact details are not consent, and the soft opt-in never covers bought-in or enriched contacts; and an organisation that has an agency send for it stays responsible. The LinkedIn note now names both risks, and the pre-launch checklist gains 3 items. `SKILL.md`'s compliance summary reflects the new points.

`SKILL.md` grows from 157 to 161 lines; the detail sits in `references/`.

## Why

- The skill already designs agents that read inbound forms, research prospect websites and summarise transcripts, then write to the CRM or draft outreach, but said nothing about hostile text. The National Cyber Security Centre's December 2025 guidance says language models draw no firm line between instructions and data, so prompt injection may never be fully mitigated; it recommends deterministic safeguards that constrain what the system can do, lowering an agent's privileges to those of the party whose content it is reading, and logging inputs, outputs and tool calls. It warns against relying on phrase blocking.
- The test protocol scored each golden-set record once. Anthropic's January 2026 guidance on evaluating agents explains that model outputs vary between runs, so it runs several trials per task, and shows the arithmetic: 75% per run gives about 42% across 3 runs. It also recommends balanced test sets, rules-based graders where possible with model graders calibrated against humans, grading the outcome rather than the path, reading transcripts of failures, and a regression suite expected to pass almost every task.
- The compliance reference told users to "check the current version" of guidance that has since settled. The regulator's February and June 2026 statements confirm commencement and the higher fines, and its electronic mail guidance (updated 28 April 2026) states that private messages on social media count as electronic mail. The skill previously treated LinkedIn messages only as a platform terms risk, which understated the legal position.

## Considered and rejected

- **Saying LinkedIn messages always need consent.** The regulator's guidance confirms they are electronic mail but does not say how the corporate-subscriber rule applies to a personal social media account. The reference flags this as an open question for the data protection lead rather than stating a rule the source does not state.
- **A fixed consistency threshold (for example "right on every run for 95% of records").** No source gives a figure for go-to-market workflows, so the threshold is left for the business owner to agree, like the other acceptance criteria.
- **Re-checking the tool landscape prices (Clay, HubSpot credits, n8n, Cargo).** The file was checked in October 2026; a pricing pass is better as its own review, against each vendor's pricing page.
- **Recommending a named evaluation framework or prompt-injection product.** Anthropic lists several frameworks but says they are only as good as the test cases; the National Cyber Security Centre warns against products claiming to stop prompt injection. The method is tool-neutral.
- **Re-checking the EU section.** Not researched in this pass; the file now says so.
- **Rewriting the skill description.** It already says what the skill does and when to use it, and there is no evidence it is being missed; the new guidance sits in the method, not the trigger.
- **Fixing the "reussable" typo in the top-level README.** Outside this agent; flagged for a separate change.
